# 导入格式说明

本文说明怎样准备能导入 miniWhale 的数据。

入口：**设置 → 📥 导入与数据 → 导入**。点开是一个底部面板：

| 分组 | 行 | 选什么 |
|---|---|---|
| 她的人设 | 📄 Soul.md | 一个 `.md` / `.txt` 文件，或导出的整包 ZIP |
| 她的人设 | 📄 User.md | 同上 |
| 内容 | 日记 | 一个或多个 `YYYY-MM-DD.md`，或一个 ZIP |
| 内容 | 记忆 | `memories.md`，或导出的整包 ZIP |
| 内容 | 聊天记录 | 导出的 ZIP（也可以直接选单个聊天 `.md`） |
| 内容 | 表情包 › | 进表情包管理页，再点「导入文件夹」或「导入 ZIP」 |

> **最省事的办法**：先在一台装了 miniWhale 的手机上点「**导出全部数据**」，得到一个 `miniWhale-<日期>.zip`（旧版本导出的叫 `小鲸鱼数据-<日期>.zip`，格式相同）。它的格式一定是对的，可以当模板照着改，也可以原样拿到新手机上导入。

两条总规则：

1. **只合并，不覆盖**。导入不会删除或改写已有的记忆、日记、聊天和表情。重复的内容会自动跳过，同一个文件导入两次也不会出现两份。唯一的例外是 Soul.md / User.md：重新导入人设文件会**替换**原来那份人设文件（User.md 拆出来的记忆仍然只增不减）。
2. **所有文本都必须是 UTF-8**。Windows 记事本「另存为」时请选 UTF-8。

## 1. 整包 ZIP 的结构

「导出全部数据」生成的 ZIP 长这样：

```
miniWhale-<日期>.zip
├── soul.md                      她的人设（没导入过就没有）
├── user.md                      关于你（没导入过就没有）
├── memory/
│   ├── memories.md              记忆（导入用这一份）
│   └── memories.json            记忆（字段完整的备份，导入时不读）
├── diary/
│   └── <YYYY-MM-DD>.md          一天一篇
├── chat/
│   └── <YYYY-MM-DD>_miniWhale.md  一天一个文件（「miniWhale」是 App 名，固定）
├── index.json                   表情库索引
├── 01/                          一个表情系列一个文件夹（文件夹名 = 系列号）
│   ├── series.json
│   └── <图片>.webp …
└── 02/
    └── …
```

**导入面板里的每一行都可以选这同一个 ZIP，每一行只取自己那一部分**：

| 行 | 在 ZIP 里找什么 |
|---|---|
| Soul.md / User.md | ZIP 里**任何位置**、文件名是 `soul.md` / `user.md` 的第一个文件，**不区分大小写**（`SOUL.md`、`User.MD` 都行） |
| 日记 | 任何位置、文件名形如 `YYYY-MM-DD.md` 的文件 |
| 记忆 | 任何位置、文件名是 `memories.md` 的文件（不区分大小写） |
| 聊天记录 | 位于名为 `chat` 的文件夹（任意层级，不区分大小写）下的 `.md` 文件 |
| 表情包 | ZIP **根目录**的 `index.json` 和各系列文件夹 |

### 大小限制

| 导入 | 限制 | 超了会怎样 |
|---|---|---|
| Soul.md / User.md | 单个文件不超过 **1,000,000 字节**（约 1 MB；从 ZIP 里取时按解压后的大小算） | 「文件超过 1 MB，先删减一些」 |
| 日记 / 记忆 / 聊天记录 | 选中的文件（或日记多选的合计）不超过 **64 MB** | 「导入失败：文件太大，不像是导出包」 |
| 同上，ZIP 内部 | 解压后合计不超过 256 MB；条目不超过 5000 个；单个文本超过 4 MB 就跳过；被选中的文本合计不超过 64 MB | 「…压缩包解压后太大 / 压缩包条目太多 / 压缩包里的文本太多，不像是导出包」 |
| 表情包 ZIP | 整包不超过 **200 MB** | 「打开文件失败：表情包超过 200 MB，没有导入」 |
| 单张表情 | 不超过 **2 MB** | 跳过这一张 |
| `series.json` / `index.json` | 不超过 1 MB | 「series.json 读不出来（不存在、读取失败或超过 1 MB）」 |

> ⚠️ **表情很多的整包要注意**：整包超过 64 MB 或者条目超过 5000 个时，表情包能导进去，日记、记忆和聊天记录却会报「文件太大 / 条目太多」。
> 遇到这种情况，把 `diary/`、`memory/`、`chat/` 三个文件夹另外压成一个小 ZIP，用这个小包导入这三项。

## 2. Soul.md 与 User.md（她的人设）

| 文件 | 作用 |
|---|---|
| **Soul.md** | 她是谁：性格、说话方式、在乎什么、你们之间的梗……整份原文放在每次对话的系统提示词最前面。没导入时，她只有一句占位人设。 |
| **User.md** | 关于你的事。原文会保存下来；导入时还会**按 `§` 拆成一条条记忆**，放进记忆页的「关于你」。 |

**格式要求**

- 纯文本或 Markdown，**UTF-8** 编码。编码不对会拒绝导入：「文件编码不是 UTF-8，转成 UTF-8 再导入」。
- 不超过 1 MB。
- **直接选单个文件时，文件名随意**（`我的人设.txt` 也行）。在哪一行选，就当哪一种导入。
- **选 ZIP 时按文件名找**：Soul.md 那一行找 `soul.md`，User.md 那一行找 `user.md`，不区分大小写，在哪个文件夹里都行。找不到会提示「打不开这个文件，换一个再试」。
- 如果文件管理器把它标成了图片、视频之类的非文本类型，会被拒绝：「只能是文本或 Markdown 文件」。文本类、`application/octet-stream`、Markdown、ZIP 都能过；标不出类型的也放行。

**User.md 怎么拆成记忆**

- **单独占一行的 `§`**（这一行去掉首尾空白后只剩 `§`）是分隔符。
- 每一条去掉首尾空白，条目内部可以换行。
- 空条目丢掉。文件里重复的条目只留第一条。
- 行内出现的 `§`（比如「第§3条」）不算分隔，`§§` 也不算。
- 拆出来的每条都放进「**关于你**」分类，来源记为「你添加的」。
- 已经有一模一样内容（去掉首尾空白后完全相同，区分大小写）的记忆不会重复添加，已有的记忆不删也不改。
- 导入成功会提示「User.md 已导入，新增 N 条记忆」。

**模板**

`Soul.md`：整份是自由文本，没有固定字段。

`User.md`：
```markdown
<关于你的第一条>
§
<第二条>
§
<第三条，可以
写成多行>
```
这份 User.md 会新增 3 条「关于你」的记忆，第三条有两行。

## 3. 日记

**文件命名**：`YYYY-MM-DD.md`，一天一个文件，例如 `<YYYY-MM-DD>.md`。

- 日期**只看文件名**，不看文件里写的标题。
- 文件名不是这个格式的直接忽略（注意扩展名写小写的 `.md`）。

**怎么选**

- 可以一次多选好几个 `.md`，也可以选一个 ZIP。
- ZIP 里的日记文件放在哪个文件夹都行（导出包里在 `diary/` 下），其余文件都忽略。
- 选中的文件名以 `.zip` 结尾时才会当成 ZIP 解开（判断的是**文件名**，所以别把 ZIP 改成别的扩展名）。

**内容格式**：日记由若干「段」组成。

- 一段 = 一行 `[HH:mm] 文字`，加上它后面所有**不以时间戳开头**的续行。
- 时间戳可以写成 `[HH:mm]`、`[H:mm]`、`[HH:mm:ss]`，行首可以有空格；导入时一律统一成 `HH:mm`（秒会丢掉）。
- **第一个时间戳之前的内容（标题、天气等）不算段，不会被导入**。
- 段尾的空行会去掉；只有时间、没有文字的段忽略。

**合并规则（只加不删）**

- 同一天里「时间相同、全文（含续行，每行去掉首尾空白后）也相同」的段跳过。
- 那一天已有的日记**一个字都不改**：标题、天气、续行、空行、顺序全都保留。
- 新段插到第一个比它时间晚的已有段前面，没有更晚的就接在末尾。时间相同时已有的段在前。
- 那一天原来没有日记的话，导入后只有这些段（第一个时间戳前面的标题不会带进来）。
- 导入完成后会提示「导入了 N 天、M 段」。

**模板** `<YYYY-MM-DD>.md`：
```markdown
<标题，可不写>
<其他说明，可不写>

[<HH:mm>] <第一段>
[<HH:mm>] <第二段第一行>
<第二段第二行>
[<HH:mm>] <第三段>
```
导入后得到 3 段，第 2 段有两行；第一个时间戳前面的内容不会导入。

## 4. 记忆

**文件**：导出包里的 `memory/memories.md`。选单个文件时，文件名随意，只要内容是这个格式。

**格式**

- `## 分类名` 开头的行设置后面条目的分类。可用的分类名：
  - `关于你`（或 `AboutYou`）
  - `约定`（或 `Agreement`）
  - `她的`（或 `Hers`）
- 以 `- ` 开头的行（前面可以有空格）是**一条记忆，一行一条**。条目内部不能换行，续行会被忽略。
- 行尾的 `（<YYYY-MM-DD>）` 或 `(<YYYY-MM-DD>)` 是导出时附带的日期，导入时会去掉。导入的记忆按导入时间记录，不用这个日期。
- 行尾的 ` · 她记下的` 表示这条是她自己记下的；不写就是「你添加的」。
- 第一个 `##` 之前的条目，以及认不出的分类下的条目，一律归到「关于你」。
- `# 记忆` 这种一级标题、空行、其他文字都忽略。

**合并规则**

- 内容（去掉首尾空白后）和已有记忆完全相同的跳过，**跨分类比较**：已经在「约定」里的同一句话，不会再加到「关于你」。
- 已有的记忆不删也不改。
- 导入完成后会提示「记忆已导入 · 新增 N 条，跳过 M 条重复」。
- 文件里一条都认不出来时，会提示「导入失败：文件里没有可导入的记忆（需要 ## 分类 和 - 内容）」。

**模板**
```markdown
# 记忆

## 关于你

- <内容>（<YYYY-MM-DD>）
- <内容>

## 约定

- <内容> · 她记下的

## 她的

- <内容> · 她记下的
```

## 5. 聊天记录

**文件**：`chat/YYYY-MM-DD_<名字>.md`，一天一个文件，导出时 `<名字>` 固定写 `miniWhale`（App 名）。旧版本导出的 `_小鲸鱼.md` 照样能导入（导入不看文件名）。

- 从 ZIP 导入时，文件必须放在名为 `chat` 的文件夹里。
- 也可以直接选一个聊天 `.md`（非 ZIP 时不检查路径）。
- **日期取自文件里的 `## YYYY-MM-DD` 标题，不看文件名**。文件名只是导出时的习惯写法。

**行格式**（逐字按解析器）

```
## <YYYY-MM-DD>
- [<HH:mm>] 她：<消息内容>
- [<HH:mm>] 我：<消息内容>
```

- `## YYYY-MM-DD` 给它下面的所有消息提供日期，可以出现多次（一个文件写多天也行）。第一个日期标题之前的消息行全部忽略。
- 消息行的格式是 `- [时:分] 说话人：内容`：
  - 开头的 `-` 前面可以有空格。
  - 小时可以是 1 位或 2 位，分钟必须是 2 位，必须是合法时间（0–23 / 0–59）。
  - 说话人**只能是 `她` 或 `我`**。`她` 是她（界面上显示你给她起的名字），`我` 是你。
  - 冒号用全角 `：` 或半角 `:` 都行，前后可以有空格。
- **一行就是一条消息**，消息里不能换行（导出时换行都已经换成空格）。内容为空的行忽略。
- `# 标题` 和其他不符合格式的行都忽略。

**图片、语音、表情怎么表示**

- 导出时，没有文字的消息写成占位符：
  - 图片：`[图片]` 或 `[图片 ×N]`
  - 语音：`[语音 7s]`
  - 文件：直接写文件名
  - 表情：写成**空内容**（`- [<HH:mm>] 我：`）
- 导入**只还原文字**：
  - `[图片]`、`[语音 7s]`、文件名会当成普通文字消息导入，不会恢复成图片、语音条或文件。
  - 空内容的表情行直接跳过。
  - 带配文的图片，导出和导入的都只有文字。

**合并与去重**

- 所有消息合并进唯一的那个对话，按时间排序。同一分钟里的消息保持文件里的先后顺序。
- 去重条件：说话人相同，文字（连续空白折叠成一个空格后）相同，时间精确到分钟也相同。
  - 库里已有一份就跳过一份，所以同一个文件导两次不会翻倍。
  - 如果某句话在同一分钟里确实说了两次，文件里也写两行，就都能导进来。
- 她正在回复时不能导入：「导入失败：她正在回复，等这一轮说完再导入」。
- 导入完成会提示「聊天记录已导入 · 新增 N 条，跳过 M 条重复」。

**模板** `chat/<YYYY-MM-DD>_miniWhale.md`：
```markdown
# <标题，可不写>

## <YYYY-MM-DD>

- [<HH:mm>] 她：<消息>
- [<HH:mm>] 我：<消息>
- [<HH:mm>] 我：[图片]
```

## 6. 表情包

> **只导入你有权使用的图片，仅供个人使用，不要分发。** 表情包只存在这台手机上（表情包管理页底部也有这句提示）。

入口：导入面板的「表情包 ›」打开表情包管理页，点「**导入文件夹**」（选一个文件夹）或「**导入 ZIP**」。

### 目录结构（格式 v2）

```
表情库根目录/            ← 选这个文件夹；做 ZIP 时要压它的「内容」，不要多套一层文件夹
├── index.json           系列清单（可选）
├── 01_<系列名>/         一个系列 = 一个文件夹
│   ├── series.json      这个系列的说明（必需）
│   └── <图片>.webp …
└── 02_<系列名>/
    ├── series.json
    └── …
```

- **一个系列 = 一个带 `series.json` 的文件夹，而且必须直接放在根目录下**。
  - 只认根目录下的一层文件夹，更深的文件夹不会被扫描。
  - 所以压 ZIP 时，`index.json` 和各系列文件夹要在 ZIP 的根上。
- 有 `index.json` 时按它列出的顺序导入；没有，或者它不是合法 JSON、`series` 为空时，就扫描根目录下的全部子文件夹（按名字排序）。
- 没有 `series.json` 的文件夹、根目录下的散图都**不导入**，会记一条「跳过」。
- 文件夹名开头如果是「两位数字 + 下划线」（比如 `01_`），这两位数字就是默认的系列号。

### `index.json`（可选）

| 字段 | 必需 | 说明 |
|---|---|---|
| `format` | 否 | 应为 `"whale-sticker-library"`，写错只警告 |
| `version` | 否 | 应为 `2`，写错只警告 |
| `series` | 是（想用 index 的话） | 数组，每项至少有 `folder` |
| `series[].folder` | 是 | 系列文件夹名。只取最后一段，必须是根目录下真实存在的文件夹，否则这个系列跳过（「index.json 里列出了，但目录不存在」） |

### `series.json`（必需）

系列级字段：

| 字段 | 必需 | 规则 |
|---|---|---|
| `format` | **是** | 必须是 `"whale-sticker-series"`，否则整个系列跳过 |
| `version` | **是** | 必须是 `2`，否则整个系列跳过 |
| `series_id` | 条件必需 | 系列号，只能用字母、数字、`_`、`-`。不写时取文件夹名开头的两位数字，两样都没有就整个系列跳过。和文件夹前缀不一致时以 `series_id` 为准（只警告） |
| `name` | 否 | 面板上显示的系列名，默认等于 `title_original` |
| `title_original` | 否 | 原标题，默认等于文件夹名 |
| `characters` | 否 | 字符串数组，系列里的角色；单张没写时用它 |
| `animated` | 否 | 是否动图，默认 `true`；单张没写时用它 |
| `has_sound_originally` | 否 | 原本是有声贴图（声音已经不在），默认 `false`。管理页会提示 |
| `source` | 否 | 来源，显示在管理页「来源：…」 |
| `license_note` | 否 | 版权说明，显示在管理页「版权：…」 |
| `stickers` | **是** | 数组，不能为空 |

每张表情（`stickers[]` 里的一项）：

| 字段 | 必需 | 规则 |
|---|---|---|
| `file` | **是** | 同一文件夹里的文件名，不能含 `/`、`\`、`..`。文件必须存在 |
| `description` | **是** | 一句话说明（建议 ≤ 12 字）。界面和对话记录里用它，例如她发表情时记录「（你发了一个表情：…）」 |
| `detail` | **是** | 详细描述（建议 30–90 字：谁、在做什么、表情细节、动起来什么样）。**她挑表情主要看这一条** |
| `id` | 否 | 对外编号，必须是 `<系列号>-<文件名去掉扩展名>`。不写或写成别的，会自动改成这个格式（改了会警告）。只能含字母、数字、`_`、`-` |
| `emotions` | 否 | 情绪词数组，只能用下面的 42 个词，表外的词丢掉并警告。一个合法词都没有也照样导入，只是她只能靠关键词找到它 |
| `text_in_image` | 否 | 图里的文字，原样抄 |
| `text_meaning` | 否 | 图里文字的简体中文意思 |
| `characters` | 否 | 这张图里的角色，不写就用系列的 |
| `couple` | 否 | 两个角色之间有亲密互动时写 `true`，默认 `false` |
| `use_when` | 否 | 适合发的场景（建议 ≤ 20 字） |
| `animated` | 否 | 覆盖系列的 `animated` |
| `needs_review` | 否 | 描述不确定时写 `true`，默认 `false` |

布尔值也接受 `"true"/"false"`、`1/0`、`"yes"/"no"`。JSON 解析比较宽松，多出来的字段会被忽略。

**图片要求**

- **只收 WebP**（静态或动态都行），按文件头 `RIFF….WEBP` 判断，改扩展名骗不过去。
  - 其他格式会跳过：「不是 WebP（只支持 WebP，请先在电脑上转换）」。
  - PNG、GIF 请先在电脑上转成 WebP。
- 单张不超过 **2 MB**。
- 张数和系列数没有单独的上限，只受整包 200 MB 限制。
- 导入时会为每张生成长边 256 的缩略图。生成失败也不影响使用。

**42 个情绪词**

- 正向：开心 大笑 兴奋 惊喜 得意 感动
- 亲密 / 关系：爱你 亲亲 抱抱 撒娇 害羞 想你 担心
- 低落 / 负面：委屈 难过 哭 生气 假凶 嫌弃 无语 无奈 尴尬 紧张 害怕 震惊
- 状态：困 心累 馋 饿 摸鱼 装傻 发呆 好奇 偷看
- 意图 / 场景：谢谢 道歉 拜托 好的 加油 早安 晚安 庆祝

**重复导入同一个系列**

- 系列号已经存在时，会先弹「确认导入」：「这些系列已经导入过：…。继续会合并：同编号更新说明，不会删掉库里已有的。」
- 合并时：
  - 同编号的表情更新说明。
  - 图片内容变了才替换，并重新生成缩略图。
  - 库里有、这次包里没有的表情保留。
  - 「她能用」开关保持你之前的设置，新系列默认打开。
  - 她发过的次数保留。

**最小模板**

```
<表情库根目录>/
├── index.json
└── 01_<系列名>/
    ├── series.json
    ├── <a>.webp
    └── <b>.webp
```

`index.json`：
```json
{
  "format": "whale-sticker-library",
  "version": 2,
  "series": [ { "folder": "01_<系列名>" } ]
}
```

`01_<系列名>/series.json`：
```json
{
  "format": "whale-sticker-series",
  "version": 2,
  "series_id": "01",
  "name": "<系列名>",
  "characters": [
    "<角色>"
  ],
  "animated": false,
  "source": "<来源>",
  "license_note": "<版权说明>",
  "stickers": [
    {
      "file": "<a>.webp",
      "id": "01-<a>",
      "description": "<一句话说明>",
      "detail": "<详细描述>",
      "emotions": [
        "<情绪词>"
      ],
      "use_when": "<适合的场景>"
    },
    {
      "file": "<b>.webp",
      "description": "<一句话说明>",
      "detail": "<详细描述>"
    }
  ]
}
```
第二张没写 `id`，导入时会自动编成 `01-<b>`。

导入结束后，管理页会显示汇总，例如「导入 <N> 个系列、<M> 张」，后面附上跳过和合并的情况。点开可以看到每一条跳过原因。

## 7. 常见提示和原因

| 提示 | 原因 / 怎么办 |
|---|---|
| 只能是文本或 Markdown 文件 | 人设导入时，系统报告的文件类型不是文本（比如被识别成图片）。把扩展名改成 `.md` 或 `.txt` 再试 |
| 文件编码不是 UTF-8，转成 UTF-8 再导入 | 人设文件是 GBK 等编码。用编辑器另存为 UTF-8 |
| 文件超过 1 MB，先删减一些 | 人设文件太大 |
| 打不开这个文件，换一个再试 | 人设：文件读不了，或者选的 ZIP 里没有 `soul.md` / `user.md` |
| 导入失败：打不开这个文件 | 记忆 / 聊天：系统没给读取权限，或文件已被删除 |
| 导入失败：文件太大，不像是导出包 | 记忆 / 日记 / 聊天：选中的文件超过 64 MB（日记多选时是合计）。见第 1 节「大小限制」 |
| 导入失败：压缩包条目太多 / 解压后太大 / 里的文本太多，不像是导出包 | ZIP 超过 5000 个条目、解压后超过 256 MB、或挑出的文本超过 64 MB。通常是整包里表情太多，把文本部分单独压一个 ZIP |
| 导入失败：文件里没有可导入的记忆（需要 ## 分类 和 - 内容） | 文件里一行 `- 内容` 都没有，或者 ZIP 里没有 `memories.md` |
| 导入了 0 天、0 段 | 文件名不是 `YYYY-MM-DD.md`；文件里没有 `[HH:mm]` 开头的行；或者内容全都已经存在 |
| 导入失败：这个包里没有聊天记录（chat/*.md） | ZIP 里没有 `chat/` 文件夹下的 `.md` |
| 导入失败：没有解析到聊天记录（需要 ## 2026-10-25 和 - [HH:mm] 她/我：内容） | 有文件但一条都没认出来：缺日期标题、说话人不是「她 / 我」、时间格式不对 |
| 导入失败：她正在回复，等这一轮说完再导入 | 等她这条说完再导 |
| 导入失败：写聊天记录失败：… | 写数据库出错，稍后重试 |
| 打开文件失败：表情包超过 200 MB，没有导入 | 表情 ZIP 太大，分几个包导 |
| 读不了这个表情包：… | 解析阶段读文件出错 |
| 没有可导入的内容 | 一个合格的系列都没有，点开看每一条跳过原因 |
| 跳过系列「…」：缺少 series.json | 这个文件夹里没有 `series.json`；或者 ZIP 多套了一层文件夹（表情库要在 ZIP 根上） |
| 跳过系列「…」：format 是 …，不是 whale-sticker-series / version 是 …，不是 2 | `series.json` 头两个字段不对 |
| 跳过系列「…」：缺少 series_id，文件夹名里也没有两位系列号 | 补 `series_id`，或者把文件夹改名为 `01_…` |
| 跳过系列「…」：series_id「…」不合法（只允许字母数字下划线） | 系列号里有中文、空格等字符 |
| 跳过系列「…」：没有 stickers 条目 / 所有贴图都没通过校验 | 看每一张的跳过原因 |
| 跳过「…」：缺少合法的 file 字段 / file 不存在 | `file` 没写、写了路径、或者文件不在同一文件夹 |
| 跳过「…」：超过 2 MB（… KB） | 压缩一下图片 |
| 跳过「…」：不是 WebP（只支持 WebP，请先在电脑上转换） | 转成 WebP |
| 跳过「…」：缺少 description / 缺少 detail | 这两个字段必填 |
| 跳过「…」：编号不合法（只允许字母、数字、下划线和连字符） | 文件名（去掉扩展名）里有中文或空格，`id` 也就不合法。把文件名改成英文和数字 |
| …忽略了不在词表里的情绪词：… | 只是警告，这张照样导入 |
